1. Executive summary

The mineral analysis service produces two tabular datasets that look almost identical — both are 275-column feature matrices over the same 255 EMIT bands — but they answer different questions and carry different labels.

Artefact What the rows are Source of the label What it is for
usgs_library/*.csv
12 files, 441 rows each		 One reference reflectance spectrum per mineral, 350–2550 nm at 5 nm spacing. None — these are the endmembers every other stage is built on. Endmembers for SAM, SMA, absorption-depth diagnostics and the synthetic forward model.
dataset_sample.csv
2 000 rows shown of 7 702		 Real EMIT pixels drawn from the scene, class-balanced across the classes SAM actually found. SAM dominant mineral + SMA abundance vector from the normal pipeline. Evaluation set: apply a trained network and compare against the classical method.
training_sample.csv
2 000 rows shown of 62 400		 Simulated reflectance spectra from a constrained linear-mixing forward model — no pixel in the scene. Ground truth by construction: the abundance vector was drawn before the spectrum was synthesised. Training set: balanced over all 12 minerals, so the network sees classes the scene cannot supply.

The single most important distinction

The evaluation set's labels are pseudo-labels: SAM and SMA were run on the real pixels first, and their output was written down as the target. A model that reproduces them has learned to imitate the classical pipeline on this scene — not to identify minerals against field truth. The training set has the opposite property: its labels are genuinely correct by construction, but its spectra are synthetic, so its realism depends entirely on how good the forward model and the library are.

The library files are not genuine USGS measurements Despite the directory name and the usgs_ prefix, the twelve CSVs are generated by spectral_library.generate_default_library_csvs() from a hard-coded table of Gaussian absorption features. Every value in them is a smooth analytic curve plus a fixed pseudo-random noise draw. There is no USGS spectral ID, no sample provenance, no grain size, no measurement geometry, and no true mineralogy behind them. Section 2 documents this in full; Section 8 explains what it means for the validity of the training set.

2. The reference library: data/usgs_library/*.csv

2.1 File format

Each file is a small CSV with three metadata/header lines followed by data rows:

# name: alunite
# wavelength_unit: nm
wavelength_nm,reflectance
350.00,0.451685
355.00,0.449832
...
2550.00,0.409527

The loader in [spectral_library.py](spectral_library.py) is deliberately strict about this layout. load_spectrum_csv() accepts optional # key: value comment lines, then finds the header row by looking for columns whose names start with wavelength and reflectance. The wavelength unit must be stated — via the function argument, a # wavelength_unit: line, or a column suffix such as _nm — and if more than one source states a unit they must agree, or the load fails.

Validation at load time rejects a spectrum if any of the following is true: wavelengths are not strictly increasing, wavelengths are non-positive or non-finite, reflectance contains NaN/inf, reflectance falls outside the declared range (default [0.0, 1.5]), or the file contains USGS “deleted channel” sentinel values near −1.23×1034. The class is [spectral_library.py:47](spectral_library.py#L47).

2.3 How each spectrum was actually generated

If the library directory is empty, spectral_library.load_library() calls generate_default_library_csvs(), which writes one CSV per entry in the _DEFAULT_MINERAL_SPECS table ([spectral_library.py:235](spectral_library.py#L235)). Each spectrum is built by _build_mineral_spectrum() as:

spectrum(λ) = base_reflectance
            + slope · (λ − λ₀)
            − Σᵢ depthᵢ · exp( −(λ − centerᵢ)² / (2·widthᵢ²) )
            + N(0, 0.002)

The grid is np.arange(350, 2551, 5) — 441 samples at 5 nm spacing — and the result is clipped to [0.01, 0.95]. The noise term uses a generator seeded from the base reflectance and slope, so the draw is deterministic and the files can be regenerated byte-for-byte.

Consequence for every downstream result These spectra are plausible, not measured. The absorption centres are in the right places for each mineral group, so SAM and SMA behave qualitatively the way they would with a real library. But the shapes are idealised Gaussians with no overlapping minor features, no continuum variability, no scattering slope from grain size, and no mixture components. Any accuracy figure computed against these endmembers is a figure about these twelve curves, not about the minerals in the ground.

2.4 How the library is aligned to the sensor

The library's native 5 nm grid does not match the EMIT band centres. Alignment happens in two steps, and the order matters:

  1. spectral_library.load_library() first puts all twelve spectra onto a common grid — it takes the wavelengths of the first spectrum as the reference and linearly interpolates any spectrum that differs.
  2. library_setup.load_aligned_library() then calls wavelength_alignment.resample_spectra() with method="linear" to put the twelve spectra onto the 255 EMIT good-band wavelengths.

Resampling is one-directional: library spectra are moved onto the sensor grid, never the reverse. [wavelength_alignment.py](wavelength_alignment.py) is explicit about this — spectra are compared by wavelength value, never by band number, so two sensors with different band counts cannot be silently confused. Targets are never extrapolated: a target wavelength outside a spectrum's valid range becomes NaN, and load_aligned_library() raises if any target wavelength (380.86–2492.78 nm) falls outside the library range (350–2550 nm). Here the library comfortably brackets the sensor, so no band is lost at this stage.

3. The scene and the band grid

3.1 Source data

Everything starts from a NASA EMIT Level-2A reflectance product delivered as a compressed zarr store: real_emit.zarr/, 553×553 pixels × 285 spectral bands, float32. [zarr_to_tif.py](zarr_to_tif.py) extracts it to the GeoTIFF real_emit_multiband_cube.tif (EPSG:4326, bbox −101.2&ldots;−100.9 longitude, 45.0&ldots;45.3 latitude) and optionally to the flat binary real_emit_good.bsq.

3.2 Band selection: 285 → 255

[band_metadata.json](band_metadata.json) records, for each of the 285 bands, its index, its centre wavelength in nanometres, and a good_quality boolean. Exactly 255 are flagged good and 30 are not. Every stage — the normal pipeline, the feature extractor, the evaluation set and the training set — uses the same 255. The flag is read by library_setup.emit_band_table():

wl, good = emit_band_table()
good_idx = np.flatnonzero(good)          # 255 indices
wl_good  = wl[good_idx]                  # 380.86 … 2492.78 nm

The 30 dropped bands cluster where the physics says they should: the deep atmospheric water vapour troughs. This shows up as two visible gaps in the feature grid, at roughly 1357–1416 nm and 1796–1974 nm, which is why the characteristic column names jump from cr_1357.2nm straight to cr_1416.8nm and from cr_1796.3nm to cr_1974.5nm. A smaller gap sits below 1975 nm near the 1900 nm water band. The masks are a property of the EMIT product and the scene's atmosphere, not of this code.

4.1 Continuum removal

[continuum.py](continuum.py) implements the standard upper-convex-hull method. For one spectrum it fits the straight-line segments of the upper convex hull through the (wavelength, reflectance) points, interpolates that hull at every band, and divides:

continuum_removed(λ) = reflectance(λ) / continuum(λ)

The hull is found with a monotone-chain scan; a point is popped when the turn it makes with the previous two is not clockwise. The result is dimensionless, divided out so that soil albedo, topography and illumination largely cancel and the absorption bands remain. Because it is a ratio, values reach exactly 1.0 at hull vertices and fall below 1.0 inside absorption features — the evaluation script treats values above 1.01 as suspicious for that reason.

Two implementation details matter for the data:

  • At least three finite bands are required; spectra with fewer come back all-NaN (MIN_VALID_BANDS = 3).
  • NaN bands are excluded from the hull and the continuum is NaN there, so the divide never manufactures a value by extrapolation.

4.2 SAM: the class label

[sam.py](sam.py) treats each spectrum as a vector and measures the angle between it and each endmember after normalising both to unit length:

θ(p, e) = arccos( (p · e) / (‖p‖ ‖e‖) )      in radians

Because both vectors are unit-normalised, brightness cancels — SAM is sensitive only to shape. In the normal pipeline it is run on the continuum-removed spectra (SAM_USE_CONTINUUM_REMOVAL = True), which additionally removes the overall slope. The class is the endmember with the smallest angle, with two sentinels: each pixel whose best angle exceeds SAM_MAX_ANGLE = 0.20 rad (about 11.5°) is labelled unknown (sentinel −1), and a pixel with no computable angle at all is invalid (sentinel −2).

On the raster these become class ids: 0 means unclassified, and ids 1–12 map to minerals through processing_metadata.json, which records them explicitly:

idMineralidMineralidMineralidMineral
1alunite4dolomite7hematite10montmorillonite
2calcite5goethite8illite11muscovite
3chlorite6gypsum9kaolinite12quartz

4.3 SMA: the abundance label

[sma.py](sma.py) solves the linear mixture model

r = E · a + ε       subject to  aᵢ ≥ 0  and  Σ aᵢ = 1

where E is the 255×12 endmember matrix and a is the abundance vector. Non-negativity is enforced by scipy.optimize.nnls. The sum-to-one constraint is not a true equality constraint in this implementation: it is a single extra equation appended to the system, weighted by SUM_WEIGHT × max|E| with SUM_WEIGHT = 1e3. The consequence is visible in the data — abundance sums come out very close to 1 but not exactly 1. The recorded mean over 7 702 samples is 0.9999989.

Crucially, SMA runs on the original reflectance, not the continuum-removed spectra. SAM and SMA are therefore looking at different representations of the same pixel, which is one reason their outputs do not always agree.

Fit quality is recorded as the residual RMSE in input units. Pixels above SMA_MAX_RMSE = 0.10 are treated as poorly modelled and are excluded from the dataset.

4.4 Quality score

[confidence.py](confidence.py) combines the SAM angle and SMA RMSE into a single heuristic in [0, 1]. The normal pipeline's own metadata is careful about what this is: “quality is a heuristic indicator, not a probability”. It is useful for sorting and thresholding; it is not calibrated against anything.

5. The feature transform

Both CSVs contain exactly 275 feature columns, and both are produced by the same class — rtm_inversion/features.py:FeatureExtractor. This is a deliberate design decision: the network is trained on synthetic spectra and applied to real pixels, so if the feature code differed by even one detail the model would face a distribution shift it cannot see.

Note that the windows overlap heavily (Al–OH, Fe–OH and Mg–OH all cover the 2200–2330 nm region; sulfate spans 600 nm). The depths are therefore correlated by construction, which is why the features are passed to a network rather than interpreted individually.

5.2 Order of operations

FeatureExtractor.transform() does the work in this order, and the order is load-bearing:

  1. Continuum-remove the incoming reflectance once; this array becomes columns 0–254.
  2. Take the minimum of that same CR array inside each window and form 1 − min.
  3. Compute SAM angles on the CR spectra against CR endmembers. The endmembers are continuum-removed once in the constructor and cached.
  4. Compute brightness from the original reflectance, not the CR version.

6. The evaluation set: dataset_sample.csv

6.1 What it is

Produced by rtm_inversion/build_dataset.py. The inputs are the GeoTIFF cube and the three reference rasters from the normal pipeline. The output is output/dataset/dataset.npz plus the readable dataset_sample.csv (first 2 000 rows), a schema and a stats file.

6.2 The selection algorithm, step by step

  1. Read the cube with the same 255 good bands the normal run used. The band count is checked against band_metadata.json and the build aborts on a mismatch.
  2. Build endmembers and extractor on the identical wavelength grid.
  3. Read the reference maps — class ids, the 12-band abundance stack, and quality — and map the 1-based class ids back onto 0-based library indices via processing_metadata.json. Unclassified pixels (id 0) are dropped.
  4. Sample. With balanced=True (the default), the cap is divided evenly across the twelve minerals:
    per_class = max_samples // 12 = 60 000 // 12 = 5 000
    For each class, up to 5 000 members are drawn without replacement; classes with fewer members contribute everything they have. The combined index list is then shuffled.
  5. Extract features for exactly those pixels and gather the matching labels, abundances and quality values.
  6. Drop non-finite rows (rows where any feature is NaN).
  7. Write the npz, the 2 000-row CSV, the schema and the stats.

6.3 Why there are 7 702 rows

The cap is per class, not global. The scene classified 5 000+ gypsum pixels and 2 702 quartz pixels and nothing else, so the balanced draw yields:

gypsum  → min(5000, 5 000) = 5 000
quartz  → min(5000, 2 702) = 2 702
                        total = 7 702

This is why dataset.npz has 7 702 rows while the documented default is 60 000. The shortfall is not a bug in sampling; it is the scene running out of classes.

7. The training set: training_sample.csv

7.1 Why it is synthetic

The scene can only supply the minerals that physically occur in it — in practice two. Training a twelve-way classifier on two classes is impossible, and training a twelve-way regressor on two is meaningless. rtm_inversion/synth.py solves this by inverting the problem: draw an abundance vector first, then synthesise the spectrum it would produce from the library, so the label is exact by construction.

1. Choose how many endmembers mix, k ∈ {1,2,3,4}
probabilities 0.30 / 0.35 / 0.25 / 0.10
▼
2. Choose which k endmembers, then draw abundances
Dirichlet(1,…,1) over the chosen members — uniform on the simplex
▼
3. Linear mixing
r₀ = Σ aᵢ Eᵢ
▼
4. Albedo nuisance
r₁ = r₀ · U(0.6, 1.2)
▼
5. Additive noise and clip
σ ~ U(0.003, 0.015); r = clip(r₁ + N(0,σ), 0.001, 1.5)
▼
6. Feature transform
FeatureExtractor — identical to the real-image path

The forward model is deliberately the same linear mixture that SMA inverts: aᵢ ≥ 0 and Σaᵢ = 1. The difference is that here the abundances are known exactly and are the regression target, whereas in the evaluation set they are estimated.

7.2 The two nuisances

Without them the network would learn the library and nothing else.

  • Brightness (a multiplicative factor in 0.6–1.2) simulates albedo, shadow, grain-size scattering and illumination differences. It is the same kind of variation continuum removal is designed to remove, so the network sees it as a nuisance it should be robust to.
  • Noise (additive Gaussian with σ in 0.003–0.015 reflectance units) simulates sensor noise and model residual.

Neither is a physical radiative-transfer simulation. There is no multiple scattering, no non-linear mixing, no spatial blur, no atmospheric residual, and no endmember variability.

7.3 Balanced coverage of all twelve minerals

Pure Dirichlet mixing would produce an unbalanced dominant-class histogram and give few clean examples of anything. The generator therefore appends pure_per_mineral = 200 spectra with abundance exactly 1.0 for each mineral, still carrying brightness and noise:

n_samples = 60 000  (mixed)
          + 12 × 200 = 2 400  (pure)

          = 62 400 rows

7.6 The learnability check

rtm_inversion/validate_nn.py trains a small scikit-learn MLP on a 75/25 split and reports class agreement, macro-F1, and abundance R²/RMSE. Both directions have been run, and the contrast between them is the clearest single piece of evidence about the two sets:

MetricTraining setEvaluation setReading
Train / test samples46 800 / 15 6005 776 / 1 92675/25 split in both
Class agreement0.9610.997both clear the 0.85 threshold
Class macro-F10.9610.997—
Abundance R²0.9860.355the decisive difference

Classes in testall 122 (gypsum, quartz)—
Why the evaluation set scores 0.997 on class but only 0.355 on abundance A two-class problem where one class dominates 65–35 is easy to get right, and the near-perfect score mostly reflects that. The abundance R² of 0.355 is the honest number: predicting a twelve-dimensional continuous mixture from 275 features on noisy, low-quality real pixels recovers roughly a third of the variance. Reporting the 0.997 alone would overstate what the pipeline can do by a wide margin.
Neither report says anything about mineral identification accuracy Both validation reports describe a model reproducing SAM/SMA — the same classical method that generated the labels. That is a consistency check (do the features carry the information the labels encode?), not an accuracy claim. The report's own wording is “the exported features reproduce the normal method”.

9. Known limitations

#LimitationWhy it mattersMitigation available in the repo
1Library is syntheticEvery accuracy figure is relative to twelve idealised Gaussians. Real library spectra differ in shape, minor features and continuum.Replace the CSVs with genuine USGS/ECOSTRESS spectra; the loader already validates whatever is dropped in.
2Only two classes in the evaluation setA twelve-way classifier cannot be evaluated. Macro-F1 of 0.997 is a two-class number.Use output/validation_synth/ for the twelve-class picture; treat the real set as a sanity check only.
3Evaluation labels are not truthA perfect score means agreement with SAM/SMA, including their mistakes.None in-repo. Requires field data or a better label source.
4Mean quality 0.037Most retained evaluation pixels are marginal fits; the abundance R² of 0.355 reflects this.Filter on quality before evaluating; re-run with a tighter SAM_MAX_ANGLE.
5SAM/SMA disagree by designSAM runs on CR spectra, SMA on original reflectance. The class label and the abundance target describe the same pixel differently.Train classification on y_class and regression on y_abund separately; do not assume they are consistent.
6Forward model is linear onlyNo non-linear mixing, no endmember variability, no spatial effects. Real intimate mixtures violate this.Section 7.2 documents exactly what is and is not modelled.
7No scale/offset appliedAPPLY_SCALE_OFFSET = False, so values are whatever the product stores. If the source is scaled integers this would matter.Verify the EMIT product's units before publication-grade work.
8Diagnostic windows overlapAl–OH, Fe–OH and Mg–OH all cover 2200–2330 nm; the seven depth features are correlated.Expected for a network input; only a problem if individual depths are interpreted causally.

10. Reproduction and file inventory

10.1 Regeneration commands

Run from services/mineral_analysis/ with the project's Python 3.13 interpreter. Note that config must be imported before rasterio — it sets PROJ_DATA to rasterio's bundled PROJ directory, without which CRS operations fail against the system PostgreSQL install.

# 1. Extract the zarr store to a georeferenced cube
python zarr_to_tif.py

# 2. Run the classical pipeline → reference maps used as labels
MINERAL_OUTPUT_DIR=output/normal_sam python main.py --good-bands-only

# 3. Build the real-image EVALUATION set
python rtm_inversion/build_dataset.py --normal-dir output/normal_sam

# 4. Build the synthetic TRAINING set
python rtm_inversion/synth.py --n-samples 60000

# 5. Convert for the NN trainer
python "rtm_inversion/NN Model/make_nn_dataset.py"

# 6. Learnability checks
python rtm_inversion/validate_nn.py

# 7. Independent audits of all three artefacts
python scripts/evaluate_data.py
python scripts/deep_check.py

Or run steps 2–4 as one chain: python -m rtm_inversion.run --good-bands-only.
